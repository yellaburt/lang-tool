# lang-tool — context for future Claude sessions

This file exists so any fresh Claude Code session on any machine can be
useful within ~2 minutes. **Read this first** when you start work on this
project.

## Who and what

A personal Spanish-reading practice tool built by Pete for daily use by:

- **Pete** (intermediate Spanish, prepping for a trip to Spain — `DPD` account)
- **Adryane** (Pete's wife, Spanish learner — `ARD` account)

## What the app does (user-facing function)

### Sign in
- Username + password (no magic links, no signups). Two accounts hard-mapped
  in code: `DPD` and `ARD`.

### Library
- A two-level tree: top-level passages, then folders, then sub-folders.
- Each row shows the passage title, how far you've read (%), and the last
  date opened.
- Each row has buttons: open (the row itself), **✎** rename, **📁** move,
  **Delete**.
- Each folder/sub-folder header has **✎** rename, **×** remove. "Remove"
  empties the folder by moving passages up a level; no passage is deleted.
- Library auto-refreshes from the server whenever you navigate to it, so
  passages saved on another device appear without a manual reload.

### Adding passages
- Paste view: paste any Spanish OR English text, then either:
  - **Save** — adds to library, processes in background, you stay in library.
  - **Start reading** — adds to library, processes, jumps to reading view
    once first batch lands.
- Titles are auto-generated by Claude (2-7 word descriptive title) shortly
  after save. If the passage is a recognizable existing work (a Vonnegut
  story, a news article), Claude often uses the real title.

### Reading mode
Each chunk runs through a sequence of phases. Defaults: Spanish audio
plays, Spanish text is visible, English gloss appears, hold for reading
time, auto-advance.

Optional phases (each user-toggleable):
- **Listening mode**: a "hidden Spanish audio" phase comes first — text
  hidden, just the audio. Then Spanish text reveals + audio replays. Then
  English reveals + (optionally) audio. Pure-listening practice.
- **English aloud**: English gloss is also read aloud.
- **Re-read**: after English, Spanish is read again, optionally in a
  contrasting voice (e.g., opposite-gender) for cross-speaker comprehension.
  Auto-skipped for chunks with ≤3 significant new words ("Howard Jones"
  doesn't get re-read). User can opt out of the auto-skip.

Controls visible at the top of the reading view:
- ⏸ Pause / ▶ Resume — freeze audio mid-utterance. Resume re-speaks the
  current chunk from the beginning (Chrome's native synth.resume is too
  unreliable to use).
- ⏮ Jump to start, ◀ Previous chunk, ↻ Replay, ▶ Next chunk.
- Settings gear (everything else: pace sliders, voice pickers, themes,
  emphasis style, re-read options, listening toggle).

Keyboard shortcuts: Space (pause/resume), ←/→ (back/next), R (replay),
Home (jump to start).

### Word lookup
- Tap any Spanish word in any visible chunk → audio pauses, a definition
  panel appears below the chunk with:
  - **Meaning** in this specific context.
  - **Verb info** if applicable: infinitive, English meaning, tense, mood,
    person/number.
  - **Idiom info** if the word is part of a fixed expression.
  - **Notes** (false-friend warnings, register hints, regionalisms).
- Definitions are cached server-side keyed on (word, chunk_text, language)
  so repeat taps anywhere are instant + free.
- Every lookup is logged to a per-user history table for future review.
- Tap × on the panel to dismiss without resuming. Tap ▶ Resume on the
  control bar to dismiss AND continue reading.

### Cross-device flow
- Save on desktop → switch to phone → open library → pull-down to refresh
  → the new passage shows up.
- All reading state (last-read chunk index, lastOpenedAt) syncs per-user.

## How it works (operational flow, not the storage layer)

### The reading loop
1. User pastes text into PasteView.
2. **Locally, in the browser**: text is split into sentences with a custom
   heuristic in `core.ts` that skips abbreviations ("Dr. Scholl" doesn't
   get split, "U.S." doesn't, "2.1 lbs" doesn't).
3. A `Passage` record gets added to React state with `chunks: []` and
   `processingStatus.kind === 'in-progress'`. The library row appears
   immediately.
4. A background effect (the **batch-fetch effect**) sees the in-progress
   passage and starts calling the chunk-and-gloss Edge Function 2 sentences
   at a time. Returned chunks get appended; `processedSentenceCount`
   advances.
5. Once the first batch lands, reading view can render the chunks. Reading
   continues to fetch ahead via prefetch — when the user is within 3 chunks
   of the end of processed content, the next batch fires.
6. ReadingView's three "speech effects" (Spanish, English, re-read) drive
   audio. Each one's "done" flag, plus the optional `listeningHiddenSpanishDone`
   for listening mode, gates a CSS-controlled visual highlight and the
   auto-advance timer.
7. When auto-advance fires, `lastReadChunkIndex` increments; the highlight
   moves to the next chunk; the effects re-run for that chunk.

### Server-side chunking + the fallback tier
The `chunk-and-gloss` Edge Function:
1. Receives 2 sentences of text + the user's auth.
2. Tries **Haiku 4.5** first with a tool-use prompt that returns
   `{ chunks: [{ tlText, englishGloss, sentenceIndex }] }`.
3. If Haiku times out (20s), refuses (returns text instead of calling the
   tool), or returns malformed output → tries **Sonnet 4.5** (30s timeout).
4. If both fail, runs a **diagnostic call** with a known-benign sentence
   ("Hola, ¿cómo estás hoy?") on Haiku.
   - Diagnostic succeeds → conclude the original was a **content refusal**.
     Return `errorKind: 'refused'` to the client. Client inserts a `[…]`
     placeholder chunk and continues to the next batch.
   - Diagnostic fails → conclude the **service is unavailable**. Return
     `errorKind: 'unavailable'` with a user-ready message.
5. **Special case HTTP 529** (Anthropic overloaded): skip the Sonnet
   fallback entirely since both models hit the same overloaded backend.
   Return immediately with `errorKind: 'overloaded'`.

The client retries transient failures up to 3 times with exponential
backoff before surfacing an error. `refused`, `unavailable`, and
`overloaded` are non-retryable — the client treats them as terminal and
shows the appropriate friendly message.

### Word lookup flow
1. User taps a word in the rendering. Each word is wrapped in a button
   (via a tokenizer that splits on punctuation/whitespace).
2. Dispatch `lookup-word` action with `word` + `chunkId`. This action
   pauses audio AND sets `wordLookup` state to `{ kind: 'loading' }`.
3. An effect notices the loading state, finds the chunk's text + passageId
   from React state, calls the `define-word` Edge Function.
4. Edge Function checks cache (shared across users, keyed on word+chunk+
   language). On hit, returns the cached definition. On miss, calls Haiku
   with a structured tool-use prompt, caches the result, returns.
5. Whether cache hit or fresh, the function ALSO writes a row to
   `word_lookup_events` for the calling user (per-user history for future
   SRS).
6. Client receives the definition, updates `wordLookup.kind = 'ready'`.
   The panel renders below the chunk and auto-scrolls into view.

### Listening mode flow
With listening mode on, each chunk runs:
1. Hidden Spanish audio (text not visible) — uses `firstVoice`.
2. Spanish text appears, Spanish audio plays again.
3. English text appears, English audio plays (if English-aloud is on;
   otherwise just the reading hold).
4. (Optional re-read) Spanish read in `secondVoice`.

Each phase is its own React `useEffect` that fires when the prior phase's
"done" flag flips true. The phase boundaries are also where the visual
highlight (`activeSide`) moves between the Spanish and English cells.

### Auto-deploy
- Cloudflare watches the GitHub repo and rebuilds + deploys the static
  site on every push.
- GitHub Actions deploys Edge Functions when files under
  `supabase/functions/` change.
- You should never need to run `wrangler deploy` or
  `supabase functions deploy` manually. Always commit + push.

## Design decisions (don't relitigate without reading)

### Functional core / imperative shell
`core.ts` is pure. All I/O lives in `app.tsx` (effects) and `supabase.ts`
(network). The reducer is pure. Keeps logic testable and side-effecting
code small.

### Switch + assertNever, not OOP
Discriminated unions with `kind` field; switches end with
`assertNever(action)`. Compiler catches missing cases. Ben prefers this
to class hierarchies / visitors; we lean into it.

### Branded ID types
`PassageId` etc. can't be mixed at compile time. Constructors live in
`core.ts` (`IdGen` interface) so the shell injects `crypto.randomUUID`
without coupling the core to a runtime.

### Hardcoded Supabase URL + publishable key
In `src/supabase.ts`. Intentional — Cloudflare's static-assets Workers
can't take env vars, and the publishable key is RLS-constrained so it's
public-safe. The real secret (ANTHROPIC_API_KEY) lives in Supabase Edge
Function secrets only.

### 2 sentences per batch
Smaller batches reduce LLM alignment errors (where Claude smushes two
sentences' English glosses into one chunk's `englishGloss`). Tried 4,
saw alignment failures on complex text. 2 is the sweet spot.

### Restart-on-resume, not synth.resume
Web Speech's native pause/resume gets stuck after a few seconds of
pause, especially in Chrome. We cancel + re-speak the current chunk on
resume. Cost: re-hearing ~1 second of audio. Benefit: it always works.

### Refused-batch placeholder is a real chunk
When the chunk-and-gloss function decides a batch was content-refused,
the client inserts a placeholder chunk with `tlText: '[…]'`. Speech
effects detect the `[` prefix and skip TTS. The user sees a visible
"skipped" marker in the reading flow but the rest of the passage works.

### Auto-suggest titles, allow override
At save time, every passage with the deterministic first-line title
gets a Claude-generated replacement (one Edge Function call per
passage). User can rename inline (✎) at any time, including before the
auto-title arrives.

### Folders are implicit
No `folders` table. Each passage has `folder text` and `subfolder text`
columns (both nullable). A folder "exists" iff some passage references
it. Renaming a folder = updating every matching passage's column.
Deleting = clearing the column on every matching passage.

## Current problems

### Functional / UX gaps
- **No undo for passage delete.** It's gone, and Supabase free tier has
  no point-in-time recovery.
- **Lookup history is collected but never shown.** The infrastructure for
  SRS-style review is in place (`word_lookup_events` table fills on every
  tap), but there's no UI to surface it. This is a TODO Pete asked for.
- **Background batch processing has no notification.** Save a passage,
  walk away — processing continues silently. The library doesn't show a
  "processing" badge per row, and there's no toast when it's done. You
  open the passage and find out via "Loading next chunks…" buffering
  text whether it's ready.
- **Refused-batch placeholder is permanent.** Once a batch shows `[…]`
  the only way to retry is delete the whole passage and re-paste.
  Should add a "retry this batch" button on placeholder chunks.
- **No multi-select or drag-and-drop for moving passages.** Moving 10
  passages into a folder is 10 separate clicks through the 📁 form.
- **Folder rename merges silently.** Renaming "News" to existing
  "Articles" merges them with no confirmation.
- **No cost visibility in-app.** Have to check console.anthropic.com.
- **Tap-to-look-up is touchy on mobile.** Easy to accidentally tap a
  word while scrolling or trying to use a control. There's no
  "tap-and-hold" alternative.
- **Listening mode + re-read enabled = 4 audio plays per chunk.** Can be
  excessive on long readings. No setting to disable re-read just within
  listening mode.

### Engineering debt
- **The system prompt is duplicated.** `src/prompt.ts` and
  `supabase/functions/chunk-and-gloss/index.ts` both define
  `SYSTEM_PROMPT`, `TOOL_*`, and the validator. Manual sync; will drift.
  Worth a build-time injection step when there's downtime.
- **Edge Function timeouts use `Promise.race`.** The underlying HTTP
  request keeps running after the local timeout fires — it doesn't block
  the function, but it still counts against Anthropic spend until it
  finishes or aborts on its own.
- **Title-suggestion fires on every passage with a default title at
  library load.** For a fresh library load with N untitled passages,
  that's N parallel Edge Function calls. Cheap but unbounded; should be
  rate-limited or batched in v2.
- **`refresh-passages` merge logic is heuristic.** When the library auto-
  refreshes, it keeps the client's version of a passage if client has
  more chunks than server. This isn't airtight — title-only divergences
  could still get overwritten.
- **Folder rename is N×UPDATE.** Renaming a folder with 50 passages is
  50 individual UPDATEs. Fine for personal libraries; problematic at
  scale.

### Web Speech API quirks (mostly worked around)
- Voices load asynchronously; we wait up to 5s before showing "no Spanish
  voice" warnings.
- `speechSynthesis.resume()` is unreliable, so we restart-on-resume.
- Chrome Android sometimes fires `voiceschanged` later than other
  platforms.
- TTS quality varies dramatically per device/voice. No way to A/B audio
  quality programmatically.

## Costs

- Anthropic: ~$0.30/month at Pete's volume (Haiku dominant). Sonnet
  fallback could push to ~$1-2/month worst case.
- Supabase free tier: 500MB Postgres, 2M Edge Function invocations,
  1GB egress. Nowhere close to limits.
- Cloudflare free tier: static-asset Worker. Effectively unlimited.
